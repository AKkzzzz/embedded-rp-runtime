# 与当前 RP-Hub 的能力差异

审计基线：

- 最新克隆 RP-Hub：`15525c6`；
- 内嵌运行时模板：0.1 Debug；
- 日期：2026-07-23。

## 结论

内嵌运行时不是“更小的 RP-Hub 皮肤”，而是面向单张卡内应用的第二层运行时。它在状态安全、卡内世界书和应用模块化方面更强；RP-Hub 在完整产品能力、模型接入和成熟度方面明显更强。

现阶段不能笼统宣称模板全面超过 RP-Hub。准确说法是：

> RP-Hub 是成熟的通用宿主；内嵌运行时是更严格、更可编程的卡内应用内核。

最新 RP-Hub 会把破限、辅助预设、Style Priority、用户资料、工具协议和 UI Template 上下文合并进系统提示，并在请求前执行 Prompt Regex。模板目前已对齐官方预设、世界书位置、基础历史、模型请求和卡内记忆，但尚未完整对齐用户资料、Style Priority、主动工具协议、Prompt Regex 后处理和原生 UI Template 上下文。

因此当前不能宣称“模型看到的消息与 RP-Hub 完全一致”。模板在状态约束、事务写入、显式递归和单舞台生命周期上更强，但生成文风、工具反应与部分上下文仍可能不同。

## RP-Hub 预设的实际注入逻辑

当前 RP-Hub 支持：

- `system`、`user`、`assistant` 三种预设角色；
- `破限`作为最前系统提示；
- 其他 system 预设合并为辅助约束；
- user/assistant 预设作为历史前的预注入消息；
- 启停、拖动排序、编辑、导入和导出。

模板对应为：

```text
system-root
  → 破限

worldbook
  → system-top / recursive dependencies

system-support
  → 防抢话
  → 防神化
  → 人格内核
  → 文风
  → 视角等

prelude
  → User 1
  → Assistant 1
  → User 2
  → Assistant 2
```

相比 RP-Hub 依赖预设名称判断“破限”，模板使用显式 `phase`，应用包可以增加自己的阶段而不修改 Prompt Compiler。

## 默认预设对齐

模板不再维护筛选或改写版本。全部官方预设按官方顺序、角色和启停状态内置；卡内运行时只负责把“破限”映射到 `system-root`，把其他 system 项映射到 `system-support`，把 user/assistant 项映射到 `prelude`。

## 下一阶段优先级

1. 补齐最新 RP-Hub 的 classicMemory 逐轮替换语义；
2. 向量 int8 压缩、主动记忆工具和任务队列；
3. Prompt Regex 与 UI Template 上下文兼容；
4. Command Registry；
5. 首个 Galgame 或战棋应用包接入。
